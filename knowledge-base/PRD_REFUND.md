# 需求规格说明书：订单部分退款

需求编号：ORD-REFUND-2026-01  
版本：2.1  
优先级：P0

## 1. 目标

在现有订单系统中增加部分退款能力，支持同一订单多次退款，保证退款金额不超额、请求幂等、并发安全、可追溯，并兼容现有整单退款接口。

## 2. 功能需求

### FR-01 退款资格校验
- 仅 `PAID`、`PARTIALLY_REFUNDED` 订单允许退款。
- `CREATED`、`PAYMENT_PENDING`、`CANCELLED`、`REFUNDED` 订单拒绝退款。
- 订单不存在返回 `ORDER_NOT_FOUND`。

### FR-02 金额校验
- 金额使用整数分。
- `amountCents` 必须大于 0。
- 金额不得大于当前可退金额。
- 当前可退金额按成功退款累计计算。
- 不允许使用 `double` / `float` 表达金额。

### FR-03 多次部分退款
- 同一订单可多次部分退款。
- 每次成功退款后重新计算可退金额。
- 例如订单支付 10000 分，第一次成功退款 3000 分，第二次成功退款 2000 分，剩余可退 5000 分。

### FR-04 订单状态流转
- 尚未发生成功退款：`PAID`。
- 成功退款累计金额大于 0 且小于支付金额：`PARTIALLY_REFUNDED`。
- 成功退款累计金额等于支付金额：`REFUNDED`。
- 失败退款不改变订单状态。
- 不存在 `PARTIALLY_REFUNDED -> PAID` 的回退。

### FR-05 退款原因
- `reason` 必填，必须为 `CUSTOMER_REQUEST`、`DAMAGED`、`MISSING_ITEM`、`PRICE_ADJUSTMENT`、`OTHER` 之一。
- `OTHER` 时 `reasonDescription` 必填，长度 1–200。
- 其他原因的 `reasonDescription` 可选，最大 200。

### FR-06 幂等
- 幂等范围为商户 + 订单 + `idempotencyKey`。
- 同一幂等键、相同请求体：返回第一次生成的退款单及其当前状态。
- 同一幂等键、不同金额或不同原因：返回 `IDEMPOTENCY_CONFLICT`。
- 幂等键不能为空，长度 8–64。
- 幂等记录至少保留 7 天；本 MVP 进程生命周期内保留即可。

### FR-07 并发保护
- 同一订单同一时刻只允许一个退款流程进入金额检查和渠道调用阶段。
- 不同订单之间不应互相阻塞。
- 订单级锁必须在成功、失败、异常路径释放。
- 不允许只依赖“先查可退金额，再调用渠道”而没有并发保护。

### FR-08 原支付渠道
- 退款渠道必须来自订单的 `paymentChannel`。
- API 不接受 `paymentChannel` 入参。
- 渠道调用必须携带原支付交易号 `paymentTransactionId`。

### FR-09 审计
每笔退款保存：退款单号、商户号、订单号、幂等键、金额、原因、原因说明、原支付渠道、原支付交易号、状态、失败码、创建时间、更新时间。

### FR-10 旧接口兼容
- 保留 `POST /api/v1/orders/{orderId}/refund`。
- 旧接口语义仍为“退还当前全部可退金额”，而不是固定退订单原始金额。
- 旧接口继续接受 `operator` 字段；缺失时沿用旧行为 `system`。
- 旧接口内部必须复用新的退款领域服务，不能保留一套绕过新校验的实现。
- 旧接口成功响应结构保持原有字段 `orderId`、`status`、`refundedAmount`。

## 3. 非功能需求

- NFR-01：所有金额计算使用 `long` 分。
- NFR-02：服务层不依赖 Web Controller。
- NFR-03：渠道失败不得产生成功退款累计。
- NFR-04：异常时锁必须释放。
- NFR-05：API 错误响应使用统一结构。
- NFR-06：核心业务逻辑应有单元测试。
- NFR-07：新增代码应遵循现有包结构，不引入不必要的第三方依赖。

## 4. 验收场景

1. 支付 10000 分，退款 3000 分成功，订单变为部分退款，可退 7000 分。
2. 随后退款 7000 分成功，订单变为已退款。
3. 已退款订单再次退款被拒绝。
4. 支付 10000 分，已成功退款 6000 分，再请求 5000 分被拒绝。
5. 渠道失败后订单状态和成功累计不变。
6. 同一幂等键相同请求重试，不产生第二次渠道调用。
7. 同一幂等键不同请求返回幂等冲突。
8. 两个并发退款请求的成功金额总和不能超过订单支付金额。
9. 原支付渠道和交易号被传入退款网关。
10. 旧整单退款接口仍能完成剩余可退金额退款。
