# ADR-001：退款领域服务与旧接口兼容

状态：Accepted

## 背景

早期系统只有整单退款接口，部分实现将订单原支付金额直接传给支付渠道。增加部分退款后，如果保留两套退款逻辑，可能绕过金额累计、幂等和并发保护。

## 决策

1. 新旧接口必须复用同一个 RefundApplicationService。
2. 旧接口在服务层先计算当前剩余可退金额，再调用统一退款流程。
3. 旧接口使用服务端生成的幂等键，避免重复点击造成重复渠道调用；本 MVP 可使用请求头 `X-Request-Id`，未提供时生成 UUID。
4. 旧接口继续返回 `refundedAmount`（元），其含义为本次退款金额，不是累计退款金额。
5. 旧接口不允许通过传入 operator 改变支付渠道或金额校验。

## 不采纳的方案

- 旧接口继续直接调用 PaymentGateway：会绕过新规则。
- 旧接口直接将原订单金额作为退款金额：部分退款后会超额。
- 删除旧接口并要求所有调用方立即迁移：不满足兼容要求。
