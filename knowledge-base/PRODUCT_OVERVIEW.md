# 产品背景与业务术语

## 1. 产品背景

Acme Commerce 是一个面向中小商户的电商订单系统。系统已支持下单、支付和整单退款的早期版本。现在商户希望在订单已支付后，能够对订单进行多次部分退款，例如订单包含三件商品，先退一件，后续再退剩余商品。

当前代码是多年迭代形成的混合工程：部分代码由人工维护，部分由 AI 辅助生成。代码中的注释、命名和实现并不总能完整表达业务规则。开发者不能假设代码现状就是完整业务规范。

## 2. 本次业务目标

增加可审计、可幂等、金额安全的部分退款能力，同时保持旧版整单退款 API 的兼容行为。

## 3. 角色

- 商户运营：在订单详情页发起退款。
- 客服：根据客户诉求发起部分或全部退款。
- 系统：校验退款额度、记录退款单、调用支付渠道模拟网关并更新订单状态。

## 4. 术语

| 术语 | 定义 |
|---|---|
| 订单应付金额 | 订单支付成功时实际支付的金额，单位为分 |
| 累计成功退款金额 | 同一订单所有成功退款单金额之和 |
| 可退金额 | 订单应付金额 - 累计成功退款金额 |
| 部分退款 | 本次退款金额大于 0 且小于当前可退金额 |
| 全额退款 | 本次退款金额等于当前可退金额 |
| 退款单 | 一次退款请求形成的独立记录 |
| 幂等键 | 调用方为一次业务退款操作提供的唯一标识 |
| 支付渠道 | 订单原支付方式，例如 `ALIPAY`、`WECHAT`、`CARD` |

## 5. 核心业务规则摘要

1. 仅已支付或部分退款状态的订单可以退款。
2. 同一订单允许多次部分退款。
3. 累计成功退款金额不得超过订单应付金额。
4. 退款金额必须为正整数分，禁止浮点金额。
5. 只有渠道返回成功的退款才计入累计成功退款金额。
6. 同一订单的退款操作必须串行化，避免并发超额退款。
7. 同一幂等键重复提交必须返回第一次请求对应的退款结果，不得再次调用渠道。
8. 退款必须沿用订单原支付渠道，不允许调用方指定另一个渠道。
9. 部分退款后订单状态为 `PARTIALLY_REFUNDED`；全部退款后为 `REFUNDED`。
10. 退款失败不改变订单累计成功退款金额及订单状态。
