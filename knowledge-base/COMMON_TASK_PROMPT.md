# Coding Agent 通用任务提示词（A/B 两组完全一致）

你正在维护一个已有的 Java 17 / Spring Boot 3 订单服务。请在当前仓库中完成以下开发任务。

## 用户口头需求

> 订单退款这块需要优化一下。运营反馈现在有些订单需要只退一部分，不一定每次都整单退。希望能支持分多次退款，避免重复点导致重复退款，同时不要影响现有调用方。顺便把必要的参数校验和异常处理补齐，代码尽量沿用现有工程风格。

## 工作要求

1. 先阅读当前代码，理解已有订单、退款、支付渠道和 API 结构，不要假设代码注释就是完整需求。
2. 根据当前可用的信息判断需求范围。若存在会导致资金、兼容性或状态语义发生重大分歧的歧义，先提出澄清问题；不要擅自发明业务规则。对于能够从可靠依据确定的内容，可以继续实现。
3. 在修改前给出简短实施计划，说明涉及的模块和潜在兼容风险。
4. 实现必要的后端功能，包括 API、参数校验、业务逻辑、状态处理、幂等、并发保护和错误处理。
5. 保持已有 API 的兼容性，不要无理由重命名或删除已有字段、类和方法。
6. 优先复用现有依赖和工程结构，不引入不必要的第三方依赖。
7. 为核心逻辑补充自动化测试，至少覆盖正常退款、边界金额、重复请求、失败场景和旧接口兼容。
8. 执行项目测试和构建。若失败，分析原因并尽可能修复。
9. 不要修改或删除与本需求无关的功能。
10. 最终汇报：
   - 实现内容
   - 关键业务规则及其依据
   - 修改文件清单
   - 测试命令及结果
   - 尚未解决的风险或假设

## 约束

- 只在当前仓库内工作。
- 不读取或修改评测专用目录（如果存在）。
- 不伪造测试结果；未执行的测试必须明确说明。
- 不要为了让测试通过而删除、弱化或绕过测试。
- 在信息不足时优先说明不确定性，而不是自行补充资金相关规则。

请开始。
