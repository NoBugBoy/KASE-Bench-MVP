# UE：订单退款交互说明

版本：1.2

## 1. 页面入口

订单详情页在订单状态为「已支付」或「部分退款」时展示「申请退款」按钮。其他状态不展示按钮。

## 2. 退款弹窗

字段：

| 字段 | 控件 | 必填 | 说明 |
|---|---|---|---|
| 本次退款金额 | 金额输入框 | 是 | 单位元，最多两位小数；前端转为分提交 |
| 退款原因 | 下拉框 + 补充说明 | 是 | 原因枚举见下方 |
| 幂等请求标识 | 系统生成 | 是 | 前端为每次用户确认操作生成 UUID；网络重试复用原值 |

退款原因枚举：
- `CUSTOMER_REQUEST`：客户申请
- `DAMAGED`：商品损坏
- `MISSING_ITEM`：缺少商品
- `PRICE_ADJUSTMENT`：价格调整
- `OTHER`：其他

当原因选择 `OTHER` 时，补充说明必填，长度 1–200 字符。其他原因的补充说明可选，最多 200 字符。

## 3. 可退款金额展示

弹窗展示：
- 原支付金额
- 已成功退款金额
- 当前可退金额

当前可退金额 = 原支付金额 - 已成功退款金额。处理中或失败的退款不从可退金额中扣除，但处理中退款会占用订单级操作锁，防止同一订单同时发起第二笔退款。

## 4. 提交与结果

- 提交时按钮进入 loading，避免用户连续点击。
- 成功：显示退款单号、本次退款金额、剩余可退金额。
- 失败：显示可理解的失败原因，允许用户修正后重新发起；重新发起必须生成新的幂等键。
- 网络超时：前端保留原幂等键，用户点击重试时复用该键。
- 重复提交：后端返回原退款单，不重复扣款/退款。

## 5. 状态展示

| 后端状态 | 页面展示 |
|---|---|
| `PAID` | 已支付 |
| `PARTIALLY_REFUNDED` | 部分退款 |
| `REFUNDED` | 已退款 |
| `FAILED`（退款单状态） | 退款失败 |
| `PROCESSING`（退款单状态） | 退款处理中 |

## 6. 本次工程范围

本 Benchmark 只实现后端 API 和领域逻辑，不要求开发前端页面。UE 用于提供业务行为、字段语义和异常场景依据。
