# 评测主持人专用：禁止提供给 Agent

此文件夹及其内容必须在 A/B 两组完成并冻结代码后才使用。

## 1. 隐藏业务断言

以下断言用于人工评审和隐藏测试设计。Agent 不得提前看到。

- 金额一律使用整数分。
- 仅 PAID / PARTIALLY_REFUNDED 可退款。
- 多次部分退款允许。
- 只累计 SUCCESS。
- 退款总额不得超过支付金额。
- 幂等键范围为 merchantId + orderId + idempotencyKey。
- 同键同请求返回原退款结果，不重复调用网关。
- 同键不同请求返回 IDEMPOTENCY_CONFLICT。
- 订单级互斥；不同订单不应被全局锁串行化。
- 网关必须使用订单原支付渠道和原支付交易号。
- 旧接口退剩余可退金额，保留旧响应字段和单位。
- 网关失败不得改变成功累计或订单状态。
- finally 路径必须释放锁。
- PROCESSING / FAILED 不计入成功退款累计。

## 2. 隐藏测试矩阵

建议由主持人将下列场景实现为独立测试，不要将测试源文件放入 Agent 可见目录。

| ID | 场景 | 预期 |
|---|---|---|
| H01 | 10000 分订单退款 3000 | SUCCESS；剩余 7000 |

| H03 | 已退款订单再退款 1 分 | ORDER_NOT_REFUNDABLE |

| H06 | amountCents=-1 | INVALID_REFUND_REQUEST |

## 3. 建议评分（100 分）

### A. 功能正确性：30 分
- H01–H08：12 分
- H09–H12：8 分
- H13–H16：6 分
- H17–H20：4 分

### B. 业务规则遵循：25 分
- 多次部分退款与状态推导：7
- 成功退款累计及金额安全：7
- 幂等语义：5
- 原支付渠道和交易号：3
- 退款原因规则：3

### C. 工程兼容性：15 分
- 旧接口路径、请求和响应兼容：8
- 旧接口复用统一领域服务：4
- 不破坏已有结构和行为：3

### D. 工程质量：15 分
- 分层合理、Controller 不承载核心业务：3
- 锁释放与并发隔离：4
- 异常处理和错误码：3
- 可读性、可维护性、无不必要依赖：3
- 测试质量：2

### E. 需求理解与澄清：10 分
- 识别资金相关歧义：3
- 识别兼容性风险：3
- 能区分已知事实与假设：2
- 最终汇报透明：2

### F. 过程效率：5 分
- 运行时间：2
- Token / 调用成本：2
- 人工干预次数：1

## 4. 严重错误扣分

以下错误应额外扣分，单项可扣 5–15 分，最终最低 0 分：
- 允许成功退款累计超过订单支付金额。
- 旧接口绕过新退款规则。
- 幂等重试再次调用渠道。
- 退款渠道可被调用方任意指定。
- 渠道失败仍计入成功累计。
- 删除旧 API 或改变旧响应字段语义。

## 5. 评分注意事项

- 测试失败应定位是功能缺陷、环境问题还是测试与契约不匹配。
- 不要仅凭 Agent 自述评分。
- 对同一问题的多个失败断言避免重复扣分。
- 对额外实现的功能，检查是否引入范围外风险。
- 如果 Agent 主动询问关键问题，主持人按统一预设答案回复；两组必须获得完全相同的答复。若不希望人工介入，则统一要求 Agent 明确记录假设。
